## Behavioral: Prioritization & Handling Conflict

### Question
"Tell me about a time you were assigned a task with a tight deadline, but also had a high-priority production bug to fix. How did you prioritize and communicate?"

This feels like a very specific example and does not fully apply to me. I have not managed tasks with tight deadlines, but I have had soft deadlines. Due to having weekly meetings with clients, usually the bugs and tasks share the same expected deadline of the following meeting. I fully believe that the route of action depends on the severity of bug and task at hand. For example, while I was working through new features on ROSSA, namely optimization and layout improvements to the data exploration page where stats are displayed, bugs were discovered within the statistics pipeline for select analysis types. I am primarily responsible for both of these features, and was charged with both of these items. I recognized that the optimizations of the data exploration page were not entirely MVP, so I targeted the bug experienced in the uploader. The system that users utilize to upload their information and generate stats needs to be robust and operational before optimization and layout changes are made to the exploration/report page.

I usually put bugs first since these projects are still in dev. Fixing the current bugs is a higher priority than creating new features while we have users actively testing. If the bug is in a non critical section of the form, it can usually wait to be fixed, but if it is a high priority bug, I will target it.

The statistics pipeline bug threatened the core integrity of the data (Uploader), while the UI improvements were enhancements. I prioritized data integrity over aesthetics to maintain system trust during the pilot phase.
